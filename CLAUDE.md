# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

JazzyChords is an AUv3 MIDI FX plugin (type `aumi`, subtype `Jzch`, manufacturer `Fmth`) for Logic Pro on Apple Silicon (macOS 15.4+, arm64 only). It turns single notes into chords: in Pads mode the 12 keys of the trigger octave each play a chord from the current bank, and in Transpose mode every key is a root for the selected chord type. The user-facing docs are in `README.md` and `USER_GUIDE.md`.

## Commands

The Xcode project is generated by XcodeGen from `project.yml`, and `*.xcodeproj/` is gitignored. Edit `project.yml`, never the project file, and run `xcodegen generate` again after adding, removing or renaming source files.

```sh
xcodegen generate
xcodebuild -project JazzyChords.xcodeproj -scheme JazzyChords -derivedDataPath build build
open build/Build/Products/Debug/JazzyChords.app   # launching the container app registers the extension
auval -v aumi Jzch Fmth                           # AU validation
```

Tests exist only for the `ChordCore` package and use Swift Testing (`@Suite`/`@Test`/`#expect`, not XCTest):

```sh
cd ChordCore && swift test
cd ChordCore && swift test --filter VoicingTests          # one suite
cd ChordCore && swift test --filter VoicingTests/drop2    # one test
```

## Architecture

There are three parts:

- **`ChordCore/`** is a pure-Swift package that holds the music theory: `ChordQuality` (interval tables), `Voicer` (voicing styles and inversions), `VoiceLeader`, `ChordBank`/`ChordSlot`, and `FactoryBanks`. It doesn't depend on AudioToolbox, so it can be unit-tested on its own.
- **`JazzyChordsAU/`** is the app extension. `JazzyChordsAudioUnit` (the `AUAudioUnit` subclass) owns the main-thread state: the bank, presets, `fullState`, and the parameter tree. `ChordKernel` is the real-time MIDI engine. The SwiftUI UI is in `UI/`, with `PluginViewModel` bridging the UI to the AU.
- **`JazzyChords/`** is the container app. Launching it registers the extension. It also loads the plugin out of process into an `AVAudioEngine` with an `AVAudioUnitSampler`, so you can test the UI and sound without opening Logic.

### Real-time constraints (most important)

The render path in `ChordKernel` must not allocate, take locks, or do ARC traffic:

- All buffers are preallocated `UnsafeMutablePointer`s that are set up in `init`/`allocate`. The render block captures the kernel `unowned(unsafe)`.
- All voicing math runs on `NoteSet`, a fixed-capacity (8) tuple-backed struct with no heap storage. Any new chord or voicing code that the kernel calls must work on `NoteSet` and must not use arrays or other collections. Loops are written as `while` loops on purpose, to avoid iterator overhead.
- The main thread talks to the audio thread only through `Synchronization.Atomic`s:
  - Parameters are stored as float bit patterns in `Atomic<UInt32>`.
  - Each pad is one packed `UInt32` (`ChordSlot.packed`: `root | qualityIndex << 8 | bass << 16`, where bass `0xFF` means none).
  - UI pad auditions go through a single-producer, single-consumer ring buffer (`audition(pad:on:)`). These use trigger slots 128–139, while slots 0–127 are incoming MIDI notes.
  - Reset is a request flag that the audio thread acts on.
- Going the other way, the kernel publishes `soundingLow`/`soundingHigh` (128-bit note bitmap) and `heldPads`. `PluginViewModel` polls them at 30 Hz on a `.common` run-loop-mode timer, so the display keeps updating while the mouse is held down on a pad.
- Strum and humanize go through a fixed-size pending-note queue (`pendingCapacity`), which is flushed in time order on each render.

### Stable identifiers (append only, never reorder)

- `Param` raw values are both the `AUParameterAddress` and the kernel's parameter slot index, and hosts save automation against them.
- `ChordQuality.all`: a quality's position is its `index`. That index is used by the kernel's packed slots and by the automatable "Chord Type" parameter. Presets save the string `id`, so `id`s must also stay unchanged. The tests check that `id`s are unique, that each quality has fewer than 255 entries, and that its intervals fit in `NoteSet.capacity - 1` (one slot is left for a slash bass).
- `ChordBank.factory` order defines the factory preset numbers.

### State and presets

- Factory presets (`number >= 0`) replace only the chord bank and leave the performance parameters as they are.
- User presets (`number < 0`) and the per-project state go through the `fullState` override, which stores the bank as JSON under a custom key and the parameters by identifier.
- After a bank change, `applyBank` pushes every slot to the kernel, and `onStateChange` tells the view model to refresh.
- Factory banks are declared in `FactoryBanks.swift` with the `s(root, qualityID, bass)` helper. An unknown quality id makes it trap through a `precondition`.
